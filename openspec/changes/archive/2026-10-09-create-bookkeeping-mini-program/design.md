# Design

## Context

当前仓库只有 OpenSpec 规划文件，尚未建立 uni-app 工程或云开发资源。实现需满足 `proposal.md` 与三份能力规范，并依赖 Node.js、微信开发者工具、小程序 AppID 和微信云开发环境。第一版是单用户个人账本，不建设独立服务器；客户端采用跨端技术栈，但首个交付目标仍是微信小程序。

## Goals / Non-Goals

**Goals:**

- 使用 uni-app、Vue 3、TypeScript 和 Vite 建立结构清晰、可测试并具备跨端扩展基础的前端。
- 将通用页面、领域逻辑和平台专有能力分层，减少未来适配其他端时的重复开发。
- 通过可信的云函数边界完成用户识别、数据校验和数据隔离。
- 使用整数分存储金额，保证账目与统计计算准确。
- 让首页、明细和统计页共享一致的月份与账目查询规则。
- 为核心校验、金额计算、汇总逻辑和数据权限建立自动化测试。

**Non-Goals:**

- 第一版不支持共享账本、多币种、预算、周期账目、票据识别或数据导入导出。
- 第一版不支持用户自定义分类，使用内置且稳定的收入、支出分类集合。
- 第一版不建设独立 Web 后台，也不交付微信小程序之外的客户端；跨端发布留待后续变更。
- 第一版不实现离线写入后的冲突合并；保存操作需要可用网络。

## Decisions

### 1. 使用 uni-app、Vue 3、TypeScript 与 Vite

客户端采用 uni-app 的 Vue 3 + TypeScript 项目模板并使用 Vite 构建。页面以 Vue 单文件组件组织，项目按页面、共享组件、状态、服务、领域逻辑和平台适配层拆分。通用界面与记账领域逻辑不得直接依赖微信专有 API，以便后续复用到 H5、支付宝小程序等目标端。

微信登录、OpenID 获取、云函数调用和微信云开发环境初始化集中封装在微信适配层。首版仅配置并验收 `mp-weixin` 构建目标；未来增加其他端时，为该端实现身份与数据服务适配器，而不是在页面中加入分散的平台判断。

备选方案是原生微信小程序或 Taro。原生方案的平台集成最直接，但页面复用到其他端的成本更高；Taro 同样支持多端，但本项目选择团队更容易采用的 Vue 生态与 uni-app。跨端框架不能消除平台能力差异，因此不承诺一次编写即可无修改发布所有端。

### 2. 所有账目读写通过云函数完成

小程序端不直接对账目集合执行读写，而是调用云函数。云函数从可信运行环境取得当前用户的微信身份，并在每次查询、修改和删除时加入所有者条件。输入校验在小程序端用于即时反馈，在云函数端再次执行以形成安全边界。

备选方案是由小程序直接访问云数据库并仅依赖数据库权限规则。直接访问代码更少，但复杂查询、所有权检查和错误映射容易分散在多个页面，因此选择云函数作为统一入口。

### 3. 使用单一账目集合和不可变的所有者标识

云数据库使用 `transactions` 集合。核心字段包括：

- `ownerOpenId`：从云函数上下文取得，创建后不可由客户端修改；
- `type`：`income` 或 `expense`；
- `amountFen`：大于零的人民币分整数；
- `categoryId`：内置分类的稳定标识；
- `occurredAt`：账目发生日期；
- `monthKey`：由发生日期派生的 `YYYY-MM`，用于月份查询；
- `note`：受长度限制的可选备注；
- `createdAt`、`updatedAt`：服务端时间。

为 `(ownerOpenId, monthKey, occurredAt)` 建立组合索引，以支持按用户和月份查询后按日期排序。分类使用客户端与云函数共享的固定定义，避免第一版引入分类集合和管理流程。

### 4. 云函数按用例划分，领域计算保持为纯函数

使用身份探测、账目创建、账目查询、账目更新、账目删除和月度统计等明确用例入口。校验、金额格式化、日期范围生成和汇总计算放入无微信运行时依赖的纯模块，以便进行快速单元测试。

月度统计云函数只查询当前用户指定月份的数据，在服务端计算收入、支出、结余、每日支出和分类支出。对第一版数据规模而言按月即时聚合足够简单且一致；暂不维护容易失配的预计算汇总集合。

### 5. 页面围绕平台无关的账目服务层组织

uni-app 页面包括首页、账目明细、记账编辑、统计和个人中心。首页读取当月汇总及最近账目；明细页按月分页读取账目；记账页复用同一 Vue 表单组件支持新增和编辑；统计页读取月度统计；个人中心显示登录和云端同步状态。

页面只依赖平台无关的身份、账目和统计服务接口。微信适配层负责调用云函数，并把返回值转换为统一的成功或业务错误结果。页面负责加载、空状态、失败重试和用户确认，不直接调用微信 API 或拼装数据库查询。

### 6. 测试分层

使用单元测试覆盖金额转换、必填校验、月份边界、排序、统计聚合和平台适配接口。使用带模拟微信上下文的数据访问测试覆盖用户隔离及增删改查。关键页面流程先通过 uni-app 的 `mp-weixin` 构建，再在微信开发者工具中人工验收，包括首次登录、记一笔、修改、删除、切换月份和更换身份验证。

## Risks / Trade-offs

- [微信云开发带来平台绑定，未来迁移到独立后端需要替换身份和数据访问层] → 页面只依赖服务接口，避免直接依赖数据库 API，并保持领域模型独立。
- [uni-app 无法完全抹平各端组件、样式和 API 差异] → 通用页面优先使用跨端支持良好的组件与 API，将条件编译限制在平台适配层，并对每个新增目标端单独验收。
- [uni-app 或其构建依赖升级可能改变生成结果] → 固定依赖版本、提交锁文件，并在升级前后执行微信构建和关键流程回归。
- [错误配置数据库权限可能泄露个人财务数据] → 禁止客户端直接读写账目集合，所有操作在云函数中依据可信 OpenID 过滤，并加入跨用户访问测试。
- [日期、时区或月末边界处理错误会造成统计错月] → 统一按 Asia/Shanghai 业务时区生成 `monthKey` 和月份区间，并覆盖月初、月末测试。
- [按月即时聚合在单用户账目非常多时会变慢] → 第一版按月查询并建立组合索引；监控实际规模后再决定是否引入分页聚合或汇总集合。
- [网络不可用时无法保存] → 保留未提交表单内容并提供重试提示；第一版不承诺离线同步。

## Migration Plan

1. 创建 uni-app 的 Vue 3 + TypeScript + Vite 工程，固定依赖版本，并验证 `mp-weixin` 构建产物可由微信开发者工具打开。
2. 建立平台无关的服务接口和微信适配层，并配置独立的开发环境云资源。
3. 创建账目集合、索引和云函数，先在开发环境以测试账号验证数据隔离。
4. 完成页面和自动化测试后，构建微信目标并通过微信开发者工具进行真机验收。
5. 为生产版本创建或绑定正式云环境，部署云函数与索引，再提交小程序审核。
6. 若发布失败，回滚小程序版本和云函数版本；数据库结构在第一版只做新增，不需要破坏性回滚。
